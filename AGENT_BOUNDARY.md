# Agent and host boundary

Code_CLI is an explicit host command interface around existing Ingridge native
workstate. It does not patch Codex or control proprietary internal model calls.
The default code fixture is a derived replay artifact from prior real work;
current local tests are actual execution, and new model generation is zero.

WorkLedger is the only workflow state writer. Reports, World Model projections,
CLI status, graphs and receipts are derived observations. They cannot promote
evidence to judgment or Human authority. Reading a stopped state grants no
new execution permission. UNKNOWN completion is held and never auto-retried.

Local scope checks are not an OS filesystem/network sandbox. The trusted host
must prevent concurrent untrusted mutation of admitted inputs. Full agent-yard
routing, RAM/encryption and remanence guarantees remain unproven. Source import
does not admit execution, outbound access or artifact export.

Original Private/canonical ledgers, author credentials, personal profile
directories and historical host-bound journals are excluded. New fixture
journals are created locally by the native engine. A moved existing journal is
not silently rebound. Archived evidence is never loaded as current authority.

YamRail AI workers still require the canonical remote Bootstrap/DELTA startup
procedure for substantive new governed work. The deterministic offline demo
creates no new AI worker context and needs no Private GitHub login.

AutoCAD: only a separately qualified, user-initiated local desktop broker may
operate an actually licensed product. CLI/environment text, installed files,
COM registration, a running process, or a fabricated test receipt cannot prove
entitlement. This candidate does not yet qualify that live broker and therefore
does not launch AutoCAD. Server/cloud/remote operation and fallback are denied.

Human release/submission approval is a separate artifact. No AI signature,
local PASS, source hash or paid-provider receipt can self-approve it.
